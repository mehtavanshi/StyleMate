# WEAK / UNDERBAKED FEATURE AUDIT — StyleMate

## Methodology

Each finding is rated on three axes (1-10 scale):
- **Impact (I)**: How much this affects user trust/experience
- **Confidence (C)**: How certain this is a real problem (not a false positive)
- **Ease (E)**: How easy to fix (higher = easier)

ICE Score = I × C × E, sorted descending.

## TOP 5 SYSTEMIC RISKS

1. **Fake Shopping Infrastructure**: Meesho/Amazon are stubs that fabricate products. The entire shopping pipeline (shop matches, style match suggestions, "Complete the Look") is built on top of these stubs. Any downstream consumer inherits deceptive data. **Fix**: Either implement real provider integrations or clearly mark as search-links with no fake product wrapper.

2. **Privacy/GDPR at Scale**: User body photos are sent to 5+ third-party APIs (including a public HF Space and China-based Kling) with no per-provider consent, no DPA, and no deletion mechanism. Combined with hardcoded `DEMO_USER_ID`, this is a production-deployable app with a demo-mode privacy model.

3. **Dead Recommendation Loop**: The LightFM feedback system, outfit caching, and `style-advice` endpoint are all built but unreachable. Users see like/dislike buttons that do nothing. The most complete shopping feature (`/style-advice`) is orphaned from the UI. This represents significant wasted engineering.

4. **Calendar Outfit Locking is Broken by Design**: Storing only `items[0]?.id` as a single integer means the calendar feature fundamentally cannot remember outfits. Wear analytics are permanently degraded. This is a schema-level issue requiring a migration.

5. **Tagging Pipeline Discards Its Best Output**: `style_tags` — the most sophisticated output of FashionCLIP — is computed, serialized, and thrown away. The DB column is always null. This silently neuters the pairing engine's style-awareness.
